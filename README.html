User Guide

Google Maps Business Scraper

A desktop application that searches Google Maps for businesses with no web presence or an outdated website — and exports the results to a formatted Excel spreadsheet ready for outreach.

Python 3.10+
Platform Windows
Launch pythonw launch.pyw

Overview

What the application does and why it is useful.

The Google Maps Business Scraper is a lead-generation tool aimed at web designers and developers. It automates the process of finding local businesses that either have no website at all or have a website that was last active before a configurable year (default: 2010). These businesses are prime candidates for a new website pitch.

🔍 What it finds
Businesses on Google Maps within specified UK postcodes that have no web presence or an outdated one — automatically flagged and colour-coded for easy review.
📄 What it produces
A formatted .xlsx Excel file with business name, address, phone, website URL, detection method, rating, and postcode — with one-click hyperlinks and colour-coded rows.
ℹ

The scraper uses a real Chromium browser behind the scenes — it behaves like a human browsing Google Maps, not a traditional web crawler. No API keys or paid subscriptions are required.

Installation

One-time setup steps before first use.

⚠

Python 3.10 or later is required. You can check your version by running python --version in a terminal.

  1. 1
    Install Python dependencies

    Open a terminal in the project folder and run:

pip install -r requirements.txt
  1. 2
    Install the Chromium browser

    Playwright needs to download a bundled Chromium. Run this once:

playwright install chromium
  1. 3
    Launch the application

    Double-click launch.pyw, or run from a terminal:

python main.py

Quick Start

Get your first results in under five minutes.

  1. 1
    Open the application

    Double-click launch.pyw. The scraper window opens. No terminal window will appear.

  2. 2
    Enter a postcode

    Type a UK postcode in the Postcodes box — for example EC1A 1BB. You can enter multiple postcodes separated by commas or new lines.

  3. 3
    Choose your filters

    Tick No website to find businesses with no web presence, and/or Outdated website to flag sites that pre-date your chosen year threshold.

  4. 4
    Click Start Scraping

    The progress bar activates and results populate the table in real time. Each row is colour-coded by status.

  5. 5
    Export to Excel

    When the scan finishes, the Export to Excel button activates. Click it and choose a save location. The file opens directly in Excel with full formatting applied.

Filter Options

Understanding what each filter does and when to use it.

🚫 No website
Businesses are included if Google Maps shows no website link in their listing. This is the most straightforward filter — the business has no web presence at all and is an obvious outreach candidate.
🕑 Outdated website
Businesses are included if the scraper determines their website was created or last significantly updated before the Outdated before year. Evidence for this comes from the website age detection chain (see Website Age Detection). A business with a website from 2006 would likely benefit from a modern redesign.
💡

Both filters can be active at the same time. The results table will contain both "No Website" and "Outdated" rows. Businesses whose website appears modern (post-threshold) are silently excluded and never shown.

Choosing the right threshold year

The default of 2010 targets websites that are 15+ years old — typically built before responsive design, mobile-first layouts, and modern security standards became standard practice. You can raise this (e.g. to 2016) to catch more businesses, at the cost of occasionally flagging sites that are functional but not cutting-edge.

How Maps Scraping Works

A detailed look at how the application extracts business data from Google Maps.

The search approach

For each postcode the scraper navigates to: 

https://www.google.com/maps/search/businesses+in+{POSTCODE}

A real headless Chromium browser is used so that JavaScript renders fully and Google Maps behaves as it would for a human visitor. The browser is launched with bot-detection countermeasures applied.

Step-by-step scraping flow

  1. 1
    Consent handling

    On first launch, Google may show a consent page (common in the UK). The scraper automatically clicks "Accept all" and waits for Maps to load.

  2. 2
    Results detection

    The scraper checks whether the page shows a list of results or a single business. If the URL immediately contains /maps/place/, it processes that one business directly.

  3. 3
    Scrolling the results list

    The scrollable feed (div[role="feed"]) is scrolled progressively. After each scroll, the scraper waits for new listing cards to appear before scrolling again — up to 20 scroll rounds — collecting all listing URLs up to the configured maximum.

  4. 4
    Parallel place visits

    Up to 3 business pages are visited simultaneously. Each page navigates to the place detail URL and extracts: name, address, phone number, website URL, and rating. Concurrent visits reduce total run time by roughly 3×.

  5. 5
    Website age checks

    All extracted website URLs for a postcode are checked concurrently (see Website Age Detection). Businesses that match the active filter(s) are emitted to the results table in real time.

Rate limiting & anti-detection

To avoid triggering Google's bot protection:

  • Random delays between 0.6–1.2 s between individual place page visits
  • Random delays between 1.5–3.0 s between different postcodes
  • The navigator.webdriver property is hidden from the page
  • A realistic Chrome user-agent string is used
  • If a CAPTCHA page is detected, the scraper pauses for 30 seconds and retries once
⚠

Google Maps does not have a public API for bulk business data. Excessive scraping at high volumes or very high speed may trigger temporary blocks. The built-in rate limiting is designed to keep usage at a normal human-browsing pace.

Website Age Detection

How the scraper determines whether a website is outdated, and in what order the checks run.

When a business has a website URL, four checks are attempted in a specific order. The first check to return a conclusive result wins — the remaining checks are cancelled to save time. Results for each unique domain are cached for the lifetime of a scrape run, so franchise chains are only checked once.

Detection chain

① WHOIS + Wayback Machine Raced concurrently

Both checks run simultaneously. Whichever finishes first with a conclusive result is used.


WHOIS — queries the domain registrar database for the domain's registration date. This is the most reliable signal: a domain registered in 2004 almost certainly means the website has been around since at least 2004.


Wayback Machine (Archive.org CDX API) — queries the Internet Archive for the earliest successful snapshot of the domain. A site first archived in 2007 is classified as outdated.

② HTML Copyright Year Scan Fallback

The homepage is fetched and parsed. The scraper searches the page footer, copyright meta tags, and full page text for patterns like © 2006, Copyright 2008, or (c) 2003. The earliest year found is used for classification.

③ HTTP Last-Modified Header Fallback

A HEAD request is sent first (no page download needed). If the server responds with a Last-Modified header, the date is parsed and compared to the threshold year. If the header is absent or ambiguous, a full GET request and HTML scan follows.

❓ Unknown Final fallback

If all four methods fail to produce a date (domain uses WHOIS privacy, no archive exists, no copyright year in HTML, no HTTP headers), the website is classified as Unknown. These rows appear in light grey in the table and export.

Classification logic

Evidence dateResult
Date < threshold year (e.g. before 2010)Outdated
Date ≥ threshold yearOK (excluded from results)
No website URL on Google MapsNo Website
Website found but no date signalUnknown

Architecture

How the components fit together under the hood.

The application follows a producer–consumer pattern. A background thread runs an asyncio event loop that drives Playwright and HTTP requests. The GUI (tkinter) runs on the main thread and is never blocked. A queue.Queue bridges the two threads safely.

MAIN THREAD (tkinter / GUI) SCRAPER THREAD (asyncio event loop) ─────────────────────────────── ───────────────────────────────────── MainWindow.start_scraping() → creates queue.Queue() → creates threading.Event() _run_scraper_thread() → Thread(daemon=True).start() ───────► → asyncio.run(_async_scrape_entry()) → after(100ms, _poll_queue) → MapsScraper.scrape() → for each postcode: _poll_queue() [every 100 ms] → scroll + collect URLs → queue.get_nowait() loop → visit 3 places in parallel → dispatch by msg["type"]: → check websites concurrently "result" → add row to table ◄────── → queue.put({"type":"result"}) "status" → update status label ◄────── → queue.put({"type":"status"}) "progress" → update progress bar ◄────── → queue.put({"type":"progress"}) "done" → re-enable controls ◄────── → queue.put({"type":"done"}) ← always
ℹ

The scraper thread is a daemon thread — it is automatically killed when the main window closes, preventing zombie browser processes. The Stop button sets a threading.Event that the scraper checks at each iteration for a clean shutdown.

Tips & Troubleshooting

Common questions and ways to get the best results.

Getting more results

  • Increase Max results / postcode to 50 or more for dense urban areas
  • Run multiple adjacent postcodes together — enter them comma-separated
  • The Unknown status rows are still worth exporting; many have no website even if the detection chain couldn't confirm the date

The scrape is slow

  • Website checks (especially WHOIS and Wayback Machine) depend on external servers — slowness is often network latency, not the app itself
  • Each postcode requires the browser to scroll and visit multiple pages; 20 results typically takes 1–3 minutes
  • Avoid running with very high Max results values on many postcodes simultaneously

The app found no results for a postcode

  • Google Maps returns very localised results — a postcode with few businesses will naturally return fewer listings
  • Try a neighbouring or broader postcode (e.g. EC1A instead of EC1A 1BB)
  • If the status bar says "No results for [postcode], skipping" — Google Maps genuinely returned nothing for that search

Results show "Unknown" for many businesses

  • Many small business websites use domain privacy (WHOIS hidden), have never been archived, have no copyright notice, and omit HTTP headers — all four checks can legitimately fail
  • Unknown does NOT mean the website is modern. It simply means the age could not be determined automatically
  • Consider manually spot-checking Unknown rows in the export before outreach

CAPTCHA warning appears in the status bar

If Google detects automated browsing, it may serve a CAPTCHA page. The scraper detects this, pauses for 30 seconds, and retries once. If the problem persists, stop the scrape, wait a few minutes, then try again with a smaller Max results value or fewer postcodes per run.

Running python main.py from a terminal (instead of launch.pyw) will show a console window with real-time debug output — useful for diagnosing unexpected behaviour.
